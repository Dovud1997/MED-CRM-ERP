# Электронная очередь и ТВ-экраны

## Состав модуля

- очередь связана с существующими пациентами, записями, врачами, филиалами и кабинетами;
- PostgreSQL хранит текущее состояние и неизменяемую историю вызовов;
- Redis Pub/Sub доставляет события на ТВ по SSE без перезагрузки страницы;
- публичный экран открывается по длинному случайному токену и не использует учётную запись сотрудника;
- аудио, видео и изображения хранятся в отдельном Docker volume `queue_media`; в БД находятся только метаданные и путь;
- интерфейс поддерживает русский, узбекский и английский языки, а режим конфиденциальности по умолчанию показывает только номер очереди.

## Локальный запуск

1. Укажите в `.env` значение `QUEUE_DISPLAY_URL=http://localhost/display`.
2. Выполните `docker compose up -d --build` — migration `000037_electronic_queue` применится автоматически.
3. Откройте «Электронная очередь», создайте кабинет, затем ТВ-экран.
4. Скопируйте показанную один раз ссылку и откройте её на телевизоре.
5. На ТВ один раз нажмите «Включить экран и звук». Это требование браузеров для autoplay. Кнопка также запросит полноэкранный режим.

## Production DNS и TLS

Создайте DNS A/AAAA-запись `ochered.onavabolaklinikasi.uz` на адрес reverse proxy и установите:

```env
QUEUE_DISPLAY_URL=https://ochered.onavabolaklinikasi.uz/display
COOKIE_SECURE=true
```

TLS 1.2+ должен завершаться на внешнем reverse proxy. Домен очереди проксируется в тот же Nginx/Next.js, что и основное приложение. Публичны только `/display/{token}` и `/api/display/{token}/...`; административные `/api/clinic/queue/...` требуют сессию и RBAC.

## Медиа и резервное копирование

Допустимые форматы: MP3/WAV/OGG, MP4/WebM, JPEG/PNG/WebP. Сервер проверяет содержимое файла, а не только расширение. Лимит запроса — 220 МБ. Файлы не выдаются по прямому пути: публичная загрузка требует действительный токен экрана и активный объект медиатеки.

В резервную копию включайте:

- PostgreSQL;
- Docker volume `queue_media`;
- секреты окружения отдельно от архива данных.

Переход на MinIO/S3 выполняется заменой storage adapter без изменения API и таблицы метаданных. До внешнего production-запуска рекомендуется добавить антивирусное сканирование загрузок и объектное versioning.

## Восстановление и диагностика

- API readiness: `/api/v1/health/ready`;
- отсутствие свежих событий: проверить Redis и SSE `/api/display/{token}/events`;
- экран продолжает периодически загружать состояние, поэтому после временного разрыва сам восстанавливается;
- ротация токена немедленно делает старую ссылку недействительной;
- действия `CALL`, `RECALL`, `START`, `COMPLETE`, `SKIP`, `CANCEL` записываются в историю и аудит.
