# Резервные копии медицинских данных

Владелец клиники может открыть раздел «Пациенты», нажать «Скачать резервную копию», задать отдельный пароль длиной не менее 12 символов и сохранить файл `.ovbk` на компьютер. Пароль не отправляется в журналы и не сохраняется системой.

Архив содержит данные только текущей организации и шифруется AES-256-GCM. Ключ выводится из пароля через Argon2id с уникальной случайной солью. Подмена или повреждение файла обнаруживаются при расшифровке.

## Правила хранения

- Хранить медицинские записи минимум 3 года; увеличить срок, если применимое законодательство или договор требует большего.
- Использовать правило 3-2-1: три копии, два разных носителя, одна копия вне помещения клиники.
- Не хранить пароль рядом с архивом. Без пароля восстановление невозможно.
- Создавать резервную копию ежедневно и после важных массовых изменений.
- Ежемесячно проверять выбранный архив командой `backupcheck`; проверка не выводит медицинские данные.

## Проверка архива

В контейнере API доступна утилита `/backupcheck`. Передайте пароль только через переменную `BACKUP_PASSWORD` и путь к смонтированному архиву. Успешная проверка подтверждает целостность, подлинность и возможность расшифровки.

Полное восстановление выполняется администратором в отдельной изолированной среде после проверки версии схемы и создания снимка текущей базы. Автоматическое восстановление через веб-интерфейс намеренно запрещено: такая операция может перезаписать действующие медицинские данные.
